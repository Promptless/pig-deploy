# Prepare PIG 0.3.6

PIG 0.3.6 pairs the supervisor and analyzer through the `PIG_*` environment
contract. The analyzer targets schema revision 5 for cloud host enrollment and
trace provenance, with PostgreSQL 15–18 and controller protocol 1.

## Select candidate artifacts

1. Build the supervisor candidate from the merged 0.3.6 source using the
   [candidate workflow](../.github/workflows/candidate.yml). Record its source
   commit and image digest. Verify that `--version` reports `0.3.6` and its OCI
   revision matches that commit.
2. Select an analyzer image published from merged application source. Execute
   `deployment-capabilities` against the [requirements](requirements/0.3.6.json).
   The image must read `PIG_*` settings and report schema revision 5. Its deployment
   verification must permit hosted policy to disable analysis; canonical analysis
   acceptance still requires analysis permission and repository access.
3. Verify anonymous image pulls and the candidate's capabilities following
   [release operations](../RELEASING.md#candidate-and-acceptance).

## Upgrade an installation

Supervisor 0.3.4 supplies `INSTRUCTION_HUB_*` environment variables, which cannot
configure the 0.3.6 analyzer. The supervisor updates its own image after worker
verification, so this transition requires a coordinated bootstrap:

1. Pause the installation with `spec.release.paused: true` before changing its
   selected release. Confirm there is no migration in progress.
2. Upgrade the Helm-managed supervisor to the verified 0.3.6 chart and immutable
   image digest. Preserve the installation's namespace, ingress, and other Helm
   values. Confirm the new supervisor is ready.
3. Select the verified stable release and resume the installation. Remove
   `spec.release.pinnedVersion` to follow stable automatically, or set an explicit
   version when the installation requires a pin.
4. Confirm the supervisor completes preflight, migration to schema 5, worker
   rollout, hosted verification, and controller convergence. Check the observed
   release and both running image digests against the manifest.

Keep the installation's analysis policy unchanged. Successful deployment
verification proves hosted connectivity and required infrastructure checks;
canonical trace analysis and Dashboard acknowledgement are separate acceptance
results. Schema-5 recovery requires a compatible image or forward repair.

## Record acceptance and publish

Collect the required reports or obtain a version-specific owner decision using
[release operations](../RELEASING.md#candidate-and-acceptance). Bind the acceptance
record to the exact source, images, and requirements. Record omitted checks and
avoid advertising untested rollback paths. Azure and GCP remain experimental.

Publication merges the immutable manifest before opening the stable catalog PR.
Follow [publication and promotion](../RELEASING.md#publication-and-promotion),
then verify public catalog consumption before updating production.
