# Prepare PIG 0.3.5

PIG 0.3.5 pairs the supervisor and analyzer through the `PIG_*` environment
contract. Both charts use `pig` values and version 0.3.5. The analyzer targets
schema revision 5 for cloud host enrollment and trace provenance, with
PostgreSQL 15–18 and controller protocol 1.

## Select candidate artifacts

1. Build the supervisor candidate from the merged 0.3.5 source using the
   [candidate workflow](../.github/workflows/candidate.yml).
   Record its source commit and image digest. Verify that `--version` reports
   `0.3.5` and its OCI revision matches that commit.
2. Select the analyzer image built from the corresponding merged application
   source. Execute `deployment-capabilities` against the
   [0.3.5 requirements](requirements/0.3.5.json).
   The image must read `PIG_*` settings and report schema revision 5.
3. Verify anonymous image pulls and the candidate's capabilities following
   [release operations](../RELEASING.md#candidate-and-acceptance).

The two images form one release. A supervisor that supplies `PIG_*` settings
requires a matching analyzer. Existing Kubernetes credential object names and
keys remain the inputs specified by `PIGDeployment`.

## Prepare installation

Source chart installs require an explicit `image.digest`. Publication embeds the
verified analyzer digest in the manual chart and the verified supervisor digest
in the bootstrap chart. Published charts therefore select the binaries checked
for this release.

Hosted Runtime requires `RUNTIME_PIG_POLICY_SIGNING_SECRET` with the existing
signing value. Complete its Secrets Manager provisioning and Kubernetes
projection before deploying Runtime. Configure analyzer Sentry with
`PIG_WORKER_SENTRY_DSN` when that integration is enabled.

## Record acceptance and publish

The [acceptance record](acceptance/0.3.5.json) binds the owner's AWS-only
publication and stable-promotion approval to the exact source, images, and
requirements. Anonymous image access, supervisor version and OCI revision, and
executed analyzer capabilities are verified.

Live clean installation, canonical trace analysis and Dashboard acknowledgement,
upgrades, pause/pin, blocked resume, secret rotation, supervisor self-update, and
recovery remain unverified for these artifacts. The approval replaces stored
cloud test reports and advertises no tested rollback paths. Azure and GCP remain
experimental.

Follow [publication and promotion](../RELEASING.md#publication-and-promotion)
after the acceptance record is reviewed and merged. Preserve the immutable
manifest commit during stable promotion. Update a pinned installation to 0.3.5
only after the published artifacts and catalog selection pass consumer checks.
